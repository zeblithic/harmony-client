# Harmony v0.2.10

**A reliability release: the node watchdog learned restraint, and presence dots learned honesty.** Field-testing v0.2.9 surfaced a chain of self-inflicted failures — an over-eager stall detector restarted a perfectly healthy idle node, the restart path could then wedge the app's networking off *permanently and silently*, and the whole time the UI kept showing peers with green presence dots as if nothing were wrong. v0.2.10 fixes every link in that chain, and adds a self-healer for messages lost into channel-history gaps. Four fixes since v0.2.9.

> ⚠️ **Alpha software — and self-sovereign by design.** Harmony is peer-to-peer: **your identity lives only on your own devices.** If you haven't already, open **Settings → Account** and export your recovery kit — there is no server-side account recovery. Expect rough edges, and please report what you find.

---

## 🚨 Fixed: a failed internal restart could silently kill networking until relaunch

Harmony's connectivity watchdog has a last-resort tier that tears down and restarts the whole networking stack. If that restart's teardown succeeded but the bring-up failed, the node stayed **down** — no networking, no error surfaced, no retry — until you quit and relaunched the app. Nothing in the UI admitted anything was wrong. v0.2.10 bounds that restart path: a failed bring-up now escalates loudly (visible connectivity error instead of a silent void), so a node that can't recover *tells you* instead of impersonating a healthy one.

## 🚨 Fixed: the watchdog restarted healthy idle nodes

The stall detector could mistake "idle" for "stalled": a node with nothing to send could fail a liveness probe on a quiet morning and get needlessly restarted — which is exactly what armed the wedge above. The detector is now **demand-gated** — it only probes when there is real traffic that isn't moving — and a half-dead link (alive at one network layer, dead at another) now gets a targeted kick that reconnects just that link, without restarting anything.

## ✨ Highlights

- **Presence dots now tell the truth.** Three states instead of two: **solid green** = confirmed live (fresh beacon), **hollow green ring** = recently here but the connection may be stale, **muted** = offline — with "last seen ~Xm ago" in the tooltip, even after a peer drops off the roster. Stale peers no longer inflate the "N online" count or light up the community and DM dots. During any future outage, dots hollow out within about a minute on your machine's own clock — they can never again stay green for the length of a blackout.
- **Missing messages heal themselves.** A rare delivery-ordering condition could leave permanent holes in a channel's history — a few messages someone sent that your copy silently skipped and never fetched again. Channel sync now detects and backfills those holes automatically, including gaps created under earlier builds, once both sides run v0.2.10.

## 🧪 What to test

- **Idle stability:** leave Harmony running overnight doing nothing. It should never self-restart — no reconnect blips on idle mornings.
- **Presence honesty:** mid-session, disconnect a peer's machine from the network. Their dot should degrade to a hollow ring within about a minute, then to offline with a "last seen" tooltip. Reconnect them and it should return to solid green within seconds.
- **History gaps:** if a community had known missing messages under earlier builds, run v0.2.10 on both sides and confirm they backfill on their own.
- **Recovery visibility:** if you can force a network environment nasty enough to defeat reconnection entirely, the app should *show* a connectivity problem — never sit silently with green dots and no traffic.

## ⚠️ Known issues

- **macOS: one Terminal command is required on first install.** Harmony deliberately ships without an Apple Developer certificate (a recurring paid program), so Gatekeeper blocks the first launch and — despite what the dialog implies — offers **no working way to approve the app through the normal flow** (no functional right-click → Open, no "Open Anyway"). After dragging Harmony to Applications, run:

  ```bash
  xattr -dr com.apple.quarantine /Applications/Harmony.app
  ```

  then launch normally. This is one-time per install and permanent policy, not a bug we can fix in a later build. Full walkthrough: [docs/install-macos.md](../install-macos.md).
