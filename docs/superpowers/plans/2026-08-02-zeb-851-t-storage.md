# ZEB-851 T-STORAGE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove every peer-supplied stamp from an eviction/TTL *decision* in the storage-records store, the relay-hold CRDT, and the DM-inbox ingest GC, so a single faulty/malicious wall clock can neither flood honest rows out of a bounded store nor backdate a live blob/DM into instant garbage collection.

**Architecture:** Three independent single-file fixes sharing only the threat model. ES adds a local receipt clock to two store records and inverts the overflow evictor to newest-received-first (mirroring the already-flood-proof `evict_pins`). RH and C11 each add a `#[serde(skip)]` local first-observation side-map to a replicated CRDT doc and key the GC deadline off it, leaving the peer stamp untouched as first-writer-wins wire metadata.

**Tech Stack:** Rust, `cargo nextest`, existing `#[cfg(test)]` unit tests colocated per module.

## Global Constraints

- All cargo commands run from `src-tauri/`.
- Lint gate: `cargo clippy --locked --all-targets --features test-fixtures --no-deps -- -D warnings`
- Test gate: `cargo nextest run --locked --workspace --all-targets --features test-fixtures --no-fail-fast`
- Format gate: `cargo fmt --all -- --check`
- **No wire-format change.** `RelayHoldEntry`, `DmInboxEntry`, `RelayHoldDoc`, `DmInboxDoc` are `CanonicalPayload`; serialized bytes must stay byte-identical. Every new local field is `#[serde(skip)]`.
- **No CRDT-convergence change.** `updated_at` / `held_at` / `deposited_at` are untouched (never clamped or rejected in `merge_from`). They remain the FWW ordering key.
- **Divergence-safe.** Every new clock is a *local, per-replica* clock, consistent with the existing churn-tolerant / resurrection-by-merge GC model.
- No new dependencies; MSRV unchanged.
- Per-task: write the failing test first, watch it fail, implement, watch it pass, then run `cargo fmt` + the clippy gate for the touched crate before committing.

```rust
/// Bounded-store overflow: evict the record with the NEWEST local
/// `received_at_ms` first (owner tiebreak) until within
/// [`MAX_TRACKED_OWNERS`]. Newest-first makes a flood self-limiting,
/// mirroring [`evict_pins`]: an attacker minting throwaway addresses and
/// publishing far-future `updated_at` evicts their OWN just-received rows,
/// while an established honest owner's row (older receipt) is never the
/// newest and survives. Keying on the LOCAL receipt clock — never the
/// peer-supplied `updated_at` — is what closes the ZEB-851 flood-evict
/// vector: a peer stamp can no longer choose the eviction victim.
fn evict_overflow<R>(map: &mut HashMap<String, R>, received_at_ms: impl Fn(&R) -> u64) {
    while map.len() > MAX_TRACKED_OWNERS {
        let victim = map
            .iter()
            .map(|(owner, r)| (std::cmp::Reverse(received_at_ms(r)), owner.clone()))
            .min()
            .map(|(_, owner)| owner);
        match victim {
            Some(owner) => {
                map.remove(&owner);
            }
            None => break,
        }
    }
}
```

Update the five call sites from `evict_stalest(&mut MAP, |r| r.updated_at)` to `evict_overflow(&mut MAP, |r| r.received_at_ms)`:
- `new()` 247 (`pledge_lists`), 248 (`backup_sets`).
- `on_pledge_list_sample` ~421 (`pledge_lists`).
- `on_backup_set_sample` ~492 (`backup_sets`).
- `on_hosting_report_sample` ~559 (`hosting_reports`) — this switches hosting from `updated_at` to its existing `received_at_ms`, closing the same flood vector for hosting reports.
